# AGENTS.md

This file provides guidance to coding agents when working with code in this repository.

Scope: `proptest/src/strategy/` — the generation-and-shrinking core of proptest, where the `Strategy` and `ValueTree` traits and every combinator live. `strategy.rs` privately declares one module per combinator (`filter`, `filter_map`, `flatten`, `fuse`, `just`, `lazy`, `map`, `recursive`, `shuffle`, `traits`, `unions`), glob-re-exports them all, and additionally exposes `pub mod statics`. For the workspace-wide build/test/lint matrix, the `#![no_std]` rules, copyright headers, and changelog/commit conventions, see the workspace-root `AGENTS.md`.

## The two central traits (`traits.rs`)

`Strategy` is the *generation* layer; `ValueTree` is the *shrinking* layer. Every combinator in this directory is a pair: a `Strategy` wrapper whose `new_tree()` builds a matching `ValueTree`.

### `Strategy`

- `#[must_use = "strategies do nothing unless used"]`, and `Strategy: fmt::Debug` — `Debug` is a hard supertrait bound (forced by `prop_flat_map`; the doc notes it can be relaxed once specialization stabilizes).
- Associated types: `type Tree: ValueTree<Value = Self::Value>` and `type Value: fmt::Debug`. `Value` duplicates `Tree::Value` purely so callers can write `-> impl Strategy<Value = T>`.
- `fn new_tree(&self, runner: &mut TestRunner) -> NewTree<Self>` is the only required method. It is expected to be **deterministic** for a given RNG state — failure persistence only saves the seed, so a non-deterministic strategy silently breaks replay. A generation failure (e.g. a filter that rejects too often) comes back as `Err(Reason)` and is reported as `TestError::Abort`.
- `NewTree<S> = Result<<S as Strategy>::Tree, Reason>` is a type alias defined here.
- Provided combinator methods (each merely constructs the wrapper named in parentheses; all take `self` by value under `Self: Sized`): `prop_map` (`Map`), `prop_map_into` (`MapInto`; prefer it over `prop_map` when `Into` suffices — clearer and cheaper), `prop_perturb` (`Perturb`), `prop_flat_map` (`Flatten<Map<Self,F>>`), `prop_ind_flat_map` (`IndFlatten<Map<Self,F>>`), `prop_ind_flat_map2` (`IndFlattenMap`), `prop_filter` (`Filter`), `prop_filter_map` (`FilterMap`), `prop_union` (`Union`), `prop_recursive` (`Recursive`), `prop_shuffle` (`Shuffle`, needs `Value: Shuffleable`), `boxed` (`BoxedStrategy`), `sboxed` (`SBoxedStrategy`), `no_shrink` (`NoShrink`). Map/perturb/filter closures are stored behind an `Arc` (so the wrappers clone cheaply) and are `Fn`, not `FnMut`, because proptest may call them arbitrarily many times and assumes a pure result.
- The three flat-maps differ only in *shrinking* (see the long doc comment on `prop_flat_map`): `prop_flat_map`/`Flatten` is dependent — it remembers the inner strategy was derived from the outer value, so both shrink while the cross-value invariant is preserved; `prop_ind_flat_map` keeps the outer value fixed (invariant holds only because the input never shrinks); `prop_ind_flat_map2` exposes both to shrinking independently (invariant *not* preserved). A shared regen budget makes nested flat-maps tractable — see `flatten.rs`.

### `ValueTree`

- `type Value: fmt::Debug`; three methods: `current(&self) -> Value`, `simplify(&mut self) -> bool`, `complicate(&mut self) -> bool`. There are deliberately **no** default impls — a strategy that doesn't shrink must opt out explicitly (see the `noshrink!` macro in `just.rs`).
- Conceptually a `low`/`current`/`high` state machine doing a binary search between a "minimally complex" value and the originally-generated value. Contract invariants: `high` always corresponds to a *failing* case, and repeated `complicate()` returns `false` only once `current` is back to what it was before the last `simplify()`.
- Return-value contract (the handshake the runner relies on): both methods return whether **internal state changed**, *not* whether `current()` changed (an implementation generally cannot tell). `simplify()` must tolerate being called again right after it returned `false`. `complicate()` need not handle being called before any `simplify()`, but must tolerate being called after it returned `false`. Usually `complicate()` returns `true` immediately after a `simplify()` that returned `true`, but rejection-sampling strategies (`Filter`, `FilterMap`, unions over filters) can violate that — they pass `strict_complicate_after_simplify: false` to the sanity checker.

### Why the state lives in the `ValueTree`

Shrink state (the low/current/high cursor, the chosen union branch, the regen budget, the shuffle distance, …) is kept *inside* the `ValueTree` rather than re-derived from the output value (QuickCheck's approach). That is what makes shrinking integrated and per-value — combinators compose because each one knows how to walk its own source — at the cost of carrying more state and being slower than QuickCheck.

### Trait objects & boxing

- `proxy_strategy!` blanket-impls `Strategy` for `Box<S>`, `&S`, `&mut S`, `Rc<S>`, `Arc<S>` by delegating `new_tree`; `Box<dyn ValueTree>` likewise delegates the `ValueTree` methods.
- `BoxedStrategy<T>(Arc<dyn Strategy<Value=T, Tree=BoxedVT<T>>>)` and `SBoxedStrategy<T>` (same, plus `Send + Sync`) are the type-erased strategies returned by `boxed()`/`sboxed()`, where `BoxedVT<T> = Box<dyn ValueTree<Value=T>>` (private alias). Both `Clone` via `Arc::clone` (cheap shallow clone). `BoxedStrategyWrapper<T>` is the internal adapter that boxes the inner `ValueTree` into `BoxedVT`. Re-box guards avoid double wrapping: `BoxedStrategy::boxed()` and `SBoxedStrategy::sboxed()` return `self`, and `SBoxedStrategy::boxed()` reuses the existing `Arc`.
- `NoShrink<T>` wraps either a `Strategy` or a `ValueTree`; its `simplify`/`complicate` always return `false`.

### `strict_complicate_after_simplify` and the sanity checker

`CheckStrategySanityOptions` (defined here) configures `check_strategy_sanity()`, the public-but-test-oriented harness that hammers a strategy's simplify/complicate contract over 1024 generated trees. The `strict_complicate_after_simplify` field (default `true`) toggles one *extra* assertion that is **not** required by the `ValueTree` contract: that `complicate()` returns `true` at least once after any `simplify()` that returned `true`. Strategies built on rejection sampling legitimately break it and pass `false`. The sibling `error_on_local_rejects` (default `false`) instead makes local rejects hard-error by setting `Config::max_local_rejects = 0`, and `_non_exhaustive: ()` keeps the struct extensible under FRU.

## Combinators, one per file

Each file pairs a `Strategy` wrapper with its `ValueTree`; closures live behind `Arc`, and `Debug` is hand-written to print `"<function>"` for the closure fields.

- `map.rs` — `Map` (`prop_map`): `current()` applies `fun` to the source value (recomputed every call, no caching); `simplify`/`complicate` delegate straight to the source, so shrinking happens entirely in source terms. Also `MapInto` (`prop_map_into`, via `Into`, deliberately *not* built on `statics::Map` because it is stable public API) and `Perturb` + `PerturbValueTree` (`prop_perturb`): `new_tree` snapshots one `runner.new_rng()` and `current()` re-invokes `fun(value, rng.clone())` with that *same* RNG every time, so the perturbation is stable across shrink steps.
- `filter.rs` — `Filter` (`prop_filter`): `new_tree` loops, calling `runner.reject_local(whence)?` (which enforces `Config::max_local_rejects`) until the predicate accepts a value. The `ValueTree` delegates `simplify`/`complicate` to the source and then runs `ensure_acceptable()` — repeatedly `complicate()`-ing the source back to an accepted value, panicking if it cannot. `Clone` resets `whence` to `"unused"`.
- `filter_map.rs` — `FilterMap` (`prop_filter_map`) with `FilterMapValueTree`: like `Filter`, but the closure returns `Option<O>`; the mapped output is cached in a `Cell<Option<O>>` so the first `current()` after (re)acceptance is free, falling back to `fresh_current()` (which recomputes and panics if the closure unexpectedly returns `None`). Preferred over `.prop_map(..).prop_filter(..)`.
- `flatten.rs` — `Flatten` (the engine behind `prop_flat_map`) with `FlattenValueTree`: `meta: Fuse<S>` shrinks the outer (strategy-producing) value-tree, `current: Fuse<inner tree>` the derived one, and it snapshots the runner via `partial_clone()`. This is where higher-order shrinking searches for a *new* failing input when the chosen inner strategy changes: `simplify()`/`complicate()` may regenerate the inner tree up to `complicate_regen_remaining` times (seeded from `Config::cases`), each consuming the runner-wide budget via `flat_map_regen()`/`Config::max_flat_map_regens`, with `final_complication` holding the value to fall back to. Also `IndFlatten` (`prop_ind_flat_map`; its `Tree` is just the inner tree, the outer collapsed to a constant) and `IndFlattenMap` (`prop_ind_flat_map2`; `Tree` is a `tuple::TupleValueTree<(outer, inner)>`, so both halves shrink independently).
- `just.rs` — `Just<T: Clone>` (a constant; `current()` clones it) and **`LazyJust<T, F: Fn() -> T>`** (calls `F` in `current()` every time — for non-`Clone` `T`, and used by `proptest-derive`; the closure must be pure), plus a blanket `Strategy`/`ValueTree` impl for bare `fn() -> T` pointers. All three use the local `noshrink!` macro (`simplify`/`complicate` return `false`). `LazyJustFn<V>` aliases `LazyJust<V, fn() -> V>`.
- `lazy.rs` — `LazyValueTree<S>` (note: **not** `LazyJust`), a value-tree whose generation is deferred to first use. Its `state` is `Initialized(S::Tree)` / `Uninitialized { strategy: LazyValueTreeStrategy<S>, runner: Box<TestRunner> }` / `Failed`; the private strategy handle is either `Rc<S>` for local tuple-union sharing or `Arc<S>` for dynamic union sharing. `maybe_init()` runs `new_tree` once, marking `Failed` on error. This deferral is what lets `Union`/`TupleUnion` avoid generating value-trees for branches they don't pick. Constructors are `pub(crate)`; the type is `pub` only so other APIs can name it as an intermediate.
- `recursive.rs` — `Recursive<T, F>` (`prop_recursive`): holds a `BoxedStrategy<T>` base plus `recurse`, `depth`, `desired_size`, `expected_branch_size`. `new_tree` computes a decaying per-level branch probability (the big comment derives the series), clamps it to ≤ 0.9 so non-recursive cases stay reachable, and folds the strategy bottom-up as nested `prop_oneof![leaf, recurse(...)]` using `float_to_weight`; the resulting `Tree` is a `Box<dyn ValueTree<Value=T>>`. Shrinking shrinks inner values and flips recursive branches back to leaves.
- `shuffle.rs` — `Shuffle` (`prop_shuffle`) with `ShuffleValueTree` and the `Shuffleable` trait (`shuffle_len`/`shuffle_swap`, prefixed `shuffle_` so the compiler won't suggest them as corrections; impl'd for `[T]`, `Vec`, `VecDeque`, and arrays `[T; 0..=32]`). `current()` clones the inner value and runs a deterministic swap pass (cloned RNG, fixed iteration order) skipping any swap wider than `dist` (a lazily-initialized `num::usize::BinarySearch` in a `Cell`, since the length isn't known until the first `current()`). `simplify()` first shrinks `dist` toward 0 (= original order), then flips `simplifying_inner` and shrinks the inner value; `complicate()` mirrors that.
- `fuse.rs` — `Fuse<T>` (with `may_simplify`/`may_complicate` flags) guards a `ValueTree` against out-of-order or post-`false` calls (complicate-before-simplify, simplify-after-`false`, etc.). It is intentionally **not** a `Strategy` method (see the type doc); construct it with `Fuse::new`. Beyond the `ValueTree` impl it exposes state-tracker helpers — `may_simplify`/`may_complicate`, `disallow_simplify`/`disallow_complicate`, `freeze` — which `Flatten` drives. (The `#[cfg(test)]` `StrictValueTree` here is a strict contract-checking fixture.)
- `unions.rs` — weighted choice. `Union<T: Strategy>` holds a private `Vec<WeightedUnionStrategy<T>>` (`WeightedUnionStrategy<T> = (u32, Arc<T>)`) over a single `T`, preserving compatibility with thread-safe type erasure; `Weighted<T> = (u32, T)` is the public input alias for `Union::new_weighted`. Typed fallible constructors validate the weight table with `UnionBuildError` (`Empty` / `ZeroWeight` / `WeightSumOverflow` / `InvalidProbability`): `Union::try_new_uniform`, `Union::try_new_weighted`, and `try_float_to_weight`; the legacy forms `new` (all weight 1), `new_weighted`, `or`, and `float_to_weight` delegate to them and keep their documented panics for the macro-facing surface (`prop_oneof!` expands to them with literal weights). `UnionValueTree` stores each option as a `LazyValueTree`, eagerly initializing only the picked one; shrinking first simplifies the picked tree, then walks to *earlier* (lower-index) options, tracking `pick`/`min_pick`/`prev_pick`. `TupleUnion<T>` is the same idea over a 2–10 element tuple of `WeightedStrategy<S>` pairs (`WeightedStrategy<T> = (u32, Rc<T>)`) — avoiding boxing/dynamic dispatch for heterogeneously-typed but same-`Value` strategies; slot 0 is a plain `LazyValueTree`, the rest `Option`, and its `TupleUnionValueTree` shares the shrink logic via the `lazy_union_value_tree_body!` macro. `pick_weighted` returns `Result<usize, Reason>`, so an all-zero-weight table aborts generation instead of panicking inside `rand`, and the picked-option lookup degrades to a `Reason` abort on an (invariant-impossible) miss. `float_to_weight(f)` maps a probability in (0,1) to a `(u32,u32)` weight pair summing to `WEIGHT_BASE = 0x8000_0000` (never producing 0) and backs `Recursive`. Feature-gating: `Union::try_new` (collects a fallible iterator) is `pub(crate)` behind `regex-syntax`, and under no-`std` `float_to_weight` pulls `FloatCore` from `num-traits` for `round()`.

### `prop_oneof!` → `Union` / `TupleUnion`

`prop_oneof!` (in `../sugar.rs`) lowers by arm count: the unweighted form `prop_oneof![a, b]` first rewrites to `1 => a, 1 => b`; a single arm collapses to the bare strategy (no union at all); **2 through 10** arms expand to `TupleUnion::new(((w0, Rc::new(s0)), …))` (static, no boxing); **11+** arms fall through to `Union::new_weighted($crate::std_facade::vec![(w, s.boxed()), …])` (the facade path keeps the expansion resolvable at any call site, in and outside the crate), where every arm is `boxed()` into a `BoxedStrategy`. Each `wN` is the relative `u32` weight.

## `statics.rs` — a deliberate workaround

`pub mod statics` provides `Filter`/`Map` variants that take **specialised traits** (`FilterFn<T>` ≈ `Fn(&T) -> bool`; `MapFn<T>`, with an associated `Output`, ≈ `Fn(T) -> Output`) and store the function **by value** rather than in an `Arc`. The point: it lets generated/derived code *name* a combinator's concrete type without dynamic dispatch and without `Arc` having to allocate a slot for a function pointer. The module is explicitly a stopgap until RFCs #1522 and #2071 (existential / `impl Trait` in type aliases) reach stable, is "subject to removal" afterward, and external code is discouraged from using it directly. `static_map` is the `pub(crate)` helper that wraps a `fn(S::Value) -> O` in `statics::Map`.

## Gotchas

- `lazy.rs` is `LazyValueTree` (deferred init), *not* `LazyJust` — `LazyJust` lives in `just.rs`. Don't conflate them.
- There is no `Strategy::fuse()`; `Fuse` is constructed via `Fuse::new` and is meant for strategy implementors, not end users.
- Names collide across modules: `Map`/`Filter` exist in both `map.rs`/`filter.rs` and `statics.rs`; the latter are reachable only as `strategy::statics::{Map, Filter}`.
- New combinators must pull allocating types (`Arc`, `Box`, `Vec`, `Cell`, …) from `crate::std_facade`, never from `std`/`alloc` directly, or the `no_std`/`alloc` builds break.
- Closures captured in `Map`/`Filter`/`Perturb`/… are `Fn` and assumed pure: proptest re-invokes them on every `current()` and throughout shrinking.
