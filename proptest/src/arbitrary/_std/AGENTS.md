# AGENTS.md

This file provides guidance to coding agents when working with code in this repository.

Scope: `proptest/src/arbitrary/_std/` — `Arbitrary` implementations for `libstd` types. The whole module is declared in `arbitrary.rs` under `#[cfg(feature = "std")]`, so it is the one `Arbitrary` tier that may name `std::` directly (the `_core`/`_alloc` siblings may not). For the `Arbitrary` trait, the entry points (`any`/`any_with`), and the impl-helper macros, see the parent `arbitrary/AGENTS.md`; for workspace-wide conventions see the root `AGENTS.md`.

## How these impls are written

Almost every impl here is one invocation of a helper macro (`arbitrary!`, `std_arbitrary_with_params!`, `wrap_ctor!`/`std_wrap_ctor_default!`/`wrap_from!`, `lazy_just!`, plus `lift1!` for the `ArbitraryF1` container lift) defined in `arbitrary/macros.rs`, `arbitrary/functor.rs`, and this tier's `_std.rs`; most strategies funnel a smaller `any::<…>()` through `strategy::statics::static_map`. The bar is low on purpose: an impl only has to *generate* a value without panicking — shrinking quality is secondary — and that contract is what each module's `#[cfg(test)] mod test { no_panic_test!(…) }` checks (it just runs `any::<T>()` over many cases asserting no panic). `_std.rs` defines the std-only shorthand macros, then lists the submodules (`env, ffi, fs, io, net, panic, path, string, sync, thread, time`).

Even though this tier may name `std::`, allocating types are still pulled from `crate::std_facade` (`Box`, `String`, `Vec`, `Arc`, `Rc`) rather than written as `std::`/`alloc::` — see the `use` lists in `ffi.rs`, `path.rs`, `string.rs`. Only genuinely std-only paths (`std::net`, `std::io`, `std::sync`, …) are named through `std::`.

## Per-module impls

- `env.rs` (`std::env`) — `Args`/`ArgsOs`/`Vars`/`VarsOs`/`JoinPathsError` via `lazy_just!` (the live iterators/error aren't `Clone`, so `LazyJust` reconstructs them by calling the std fn each time). `JoinPathsError` is forged by `join_paths` over a deliberately-invalid separator, with platform-split `jpe()` (`:` off Windows, `"` on Windows). `VarError` lives in an inner `mod var_error` gated `#[cfg(not(target_arch = "wasm32"))]` and is a `prop_oneof!` of `NotPresent` and `NotUnicode(<invalid OsString>)`; the invalid `OsString` is platform-specific — Windows builds one from a `u16` buffer corrupted by `make_utf16_invalid` (a bit-twiddling helper gated `#[cfg(any(target_os = "windows", test))]` and fuzzed by its own 65536-case proptest), non-Windows reuses `string::not_utf8_bytes(true)` via `OsStringExt::from_vec`. `// FIXME: SplitPaths` notes the lifetime gap.
- `ffi.rs` (`std::ffi`) — `CString` (`SFnPtrMap<VecStrategy<RangeInclusive<u8>>, Self>`, `Parameters = SizeRange`): generates `1..=u8::MAX` bytes (never 0) directly within the requested `SizeRange`, then calls `CString::new`, so no interior nul is possible. `OsString` (`Parameters = <String as Arbitrary>::Parameters`) maps from an arbitrary `String`. A local `dst_wrapped!` macro wires the DST-pointer wrappers `Box<CStr>`/`Box<OsStr>`, and — only under `#[cfg(feature = "unstable")]` — also `Rc`/`Arc` of `CStr`/`OsStr`. Error types: `FromBytesWithNulError` (build bytes with an interior/empty nul, take `from_bytes_with_nul(..).unwrap_err()`) and `IntoStringError` (`not_utf8_bytes(false)` → `CString::new(..).into_string().unwrap_err()`).
- `fs.rs` (`std::fs`) — only `DirBuilder` (`SMapped<bool, Self>`, toggling `.recursive(..)`); `// TODO: other parts`.
- `io.rs` (`std::io`) — a `buffer!` macro emits `BufReader`/`BufWriter`/`LineWriter` (each `SMapped<(A, Option<u16>), Self>`, choosing `with_capacity` vs `new`, each with a `lift1!`). Combinators over arbitrary inner readers/writers: `Chain`, `Cursor` (`std_wrap_ctor_default!` for `Cursor::new`), `Lines` (`wrap_ctor!([BufRead] …, BufRead::lines)`), `Repeat`, `Split`, `Take` (the last two with `lift1!`). Unit handles `Empty`/`Sink`/`Stderr`/`Stdin`/`Stdout` via `lazy_just!`. `ErrorKind` is a `Union<Just<Self>>` over a **hand-maintained** explicit variant list (`// TODO: watch this type for variant-additions`). `SeekFrom` is a `prop_oneof!` of `Start`/`End`/`Current`; `Error` maps `(ErrorKind, Option<String>)` through `Error::new`/`kind.into()`. `// TODO: IntoInnerError`.
- `net.rs` (`std::net`) — `Ipv4Addr` is a *weighted* `prop_oneof!` biased toward `0.0.0.0` (1) and `127.0.0.1` (4) over a random `u32` (10); `Ipv6Addr` favors v4-mapped (2) over random `[u16; 8]` (1). `SocketAddrV4`/`SocketAddrV6` map address+port (+ flowinfo/scope_id) tuples; `IpAddr`/`SocketAddr` are v4|v6 unions; `Shutdown` is a 3-variant union. `AddrParseError` is a constant `Just` (`"".parse::<Ipv4Addr>().unwrap_err()`). `Ipv6MulticastScope` (7-variant union) is `#[cfg(feature = "unstable")]`. `// TODO:` real networking semantics remain open.
- `panic.rs` (`std::panic`) — `AssertUnwindSafe<A>` only, via `wrap_ctor!(AssertUnwindSafe, AssertUnwindSafe)` (maps arbitrary `A` through the tuple-struct ctor, plus a `lift1!`).
- `path.rs` (`std::path`) — `PathBuf` (`Parameters = PathParams`, defined in `src/path.rs`) generates absolute-or-relative with equal probability, pushing `MAIN_SEPARATOR` when absolute and stripping embedded separators from each component. Its `Strategy` is `SMapped<PathParamsOutput, Self>` where `PathParamsOutput` is a deliberately-unnameable `pub` struct (`is_absolute`, `components`) that *hides* the `PathParams` output shape so the public `Strategy` type stays stable if more parameters are added. Doc'd non-goals: no non-UTF-8 paths, no Windows `PrefixComponent`. `dst_wrapped!(Box, Rc, Arc)` gives `Box`/`Rc`/`Arc<Path>` by mapping from `PathBuf`. `StripPrefixError` is a constant `Just`.
- `string.rs` (`std::string`) — the most intricate file. `String` is special: `Parameters = StringParam`, `Strategy = &'static str`, and the strategy *is* the regex source (panics if it isn't a regex proptest can handle). `dst_wrapped!(Box, Rc, Arc)` gives `Box`/`Rc`/`Arc<str>`. `FromUtf16Error`/`FromUtf8Error` come from `multiplex_alloc!`-aliased std/alloc types. The shared engine is `pub(super) fn not_utf8_bytes(allow_null)`: it concatenates a valid UTF-8 prefix with an "error-length" suffix from `gen_el_bytes`, whose `ELBytes` enum + ranges encode an exhaustive analysis of `core`'s `run_utf8_validation` (covering `error_len` ∈ {None, Some(1), Some(2), Some(3)} across byte widths 2/3/4) so the result is *guaranteed* invalid UTF-8. This helper is reused by `ffi.rs` and `env.rs`.
- `sync.rs` (`std::sync`) — **no `Arbitrary` impls exist for `Mutex`, `RwLock`, `Condvar`, or `WaitTimeoutResult`**: the poisoning-prone std locks are banned types under the strict lint policy, and `WaitTimeoutResult` cannot be produced without them; compile-fail fixtures under `proptest/tests/fail/` pin all four absences, and the top-of-file comments record them alongside the pre-existing `OnceState`/`PoisonError`/`TryLockError`/`Weak` notes. What remains: `Barrier` (from a `u16` — "usize would be extreme!") and `Once` (`lazy_just!`); `BarrierWaitResult` is produced by exercising the runtime panic-free — `thread::Builder::spawn` obtains a second participant (degrading to the leader result if the OS cannot spawn a thread), and the child is always joined. Channel endpoints (`(Sender, Receiver)`, `(Sender, IntoIter)`, and the `SyncSender` variants sized by a `u16`) are only ever generated **as pairs** — generating half would hang. Errors (`RecvError`, `SendError<T>`, `RecvTimeoutError`, `TryRecvError`, `TrySendError<T>`) are direct.
- `thread.rs` (`std::thread`) — only `Builder` (`SMapped<(Option<usize>, Option<String>), Self>`, with `option::prob(0.7)` making stack-size/name present ~70% of the time). A large commented-out `JoinHandle` impl is kept with a note that its semantics are debatable (a CoArbitrary-based approach would be preferable).
- `time.rs` (`std::time`) — `Duration` from `(u64, u32)`. `Instant` is a constant `Just(Self::now())` (it "never" repeats, so it can't shrink). `SystemTime` deliberately caps seconds at `i32::MAX` (to dodge add-overflow panics, nodding to an OS that still uses `i32` seconds) and offsets `UNIX_EPOCH` forward or backward.

## Gotchas

- Keep the tiers honest: an impl that only needs `core` or `alloc` belongs in `_core/` or `_alloc/`, not here — that separation is what lets the `no_std` and `alloc`-only builds compile. Mirror it in the `use` lists too: take allocating types from `crate::std_facade`, reach for `std::` only for genuinely std-only APIs.
- Several impls trade shrinking for the ability to construct a value at all: constant `Just`s (`Instant`, `AddrParseError`, `StripPrefixError`, `RecvError`), `lazy_just!` resources, and the thread-driven `BarrierWaitResult` don't meaningfully minimize — that's expected, the `no_panic_test!` contract only demands no panic.
- `io::ErrorKind` (and any similar exhaustive-variant union) is a manual list: when std adds variants it must be updated by hand.
- Watch the feature/target gates when editing: `unstable` changes `ffi` (`Rc`/`Arc<CStr|OsStr>`) and `net` (`Ipv6MulticastScope`); `env::var_error` is off under `wasm32`; `env::make_utf16_invalid` and parts of `env`/`string` branch on `target_os = "windows"`.
