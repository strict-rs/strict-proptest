# AGENTS.md

This file provides guidance to coding agents when working with code in this repository.

Scope: `proptest/src/test_runner/` — the engine that drives test execution and shrinking. It owns the `TestRunner` loop, the `Config` / `PROPTEST_*` env-var surface, the seedable `TestRng`, legacy and native typed outcomes, the result cache, fork replay, and scoped panic-hook handling. `test_runner.rs` exports the public configuration, errors, persistence, outcome, reason, cache, RNG, and runner contracts, plus `CaseOrigin`, `PropertyTransport`, and `DecodedEvaluation`. Execution adapters, replay channels, and process supervision remain internal. For the build/test matrix, the no-`std` rules, copyright headers, and commit conventions see the workspace-root `AGENTS.md`.

## Shared generation and shrinking

`TestRunner::run` and `run_one` preserve the legacy callback contract through `LegacyExecution`. `run_typed` and `run_typed_with_transport` use `TypedExecution` to retain `Result<A, E>` payloads. Both adapters use `run_with_execution`, `run_case`, and the same shrink walk. Fork or timeout on `run_typed` fails before callback admission; `run_typed_with_transport` uses the explicit codec only when forking is configured.

- Load persisted failing seeds through `Config::failure_persistence` and replay them **first**, in reverse order, each with `is_from_persisted_seed = true`. The live RNG is cloned aside and restored around this phase so persisted replays don't perturb the main sequence.
- Then loop `while successes < config.cases`: call `rng.gen_get_seed()`, generate and evaluate one case, and on `RunFailure::Falsified` persist the seed and established counterexample unless execution is in a child. The parent owns regression persistence.
- `gen_and_run_case` builds the input with `strategy.new_tree(self)` and passes its `ValueTree` to `run_case`. Generation errors become `RunFailure::Aborted`. Only `NewCaseSuccess` / `ReplayFromForkSuccess` increment `successes`; persisted, cache-hit, and reject outcomes do not count toward `cases`.
- `run_case` evaluates through the selected adapter, retaining the observed candidate together with its failure before shrinking. Legacy rejection charges `reject_global`; typed assertion errors are falsifications, and typed preconditions belong in strategies.

Legacy `call_test` consults marker replay, pings the fork file, checks cached identities, and invokes the callback. Typed execution owns an ordered evaluation vector, records native returned subjects and failures, and uses `EvaluationId` for cache hits. Under `std`, both adapters supervise unwinding and completed callbacks that exceed the timeout. Typed timeout evidence retains the returned subject; an interrupted callback never fabricates an assertion error. The `no_std` path invokes callbacks directly.

## The shrink loop (`shrink` in `runner.rs`)

`shrink` owns the last established `(failure, counterexample)` pair independently of the value tree. Zero iterations return that pair unchanged. `walk_shrinks` simplifies after failure and complicates after pass/rejection; only a new failing evaluation replaces the pair. Iteration/time budgets can cause backtracking but never reevaluation of the retained failure. Typed replay records budget and backtrack decisions, so parent replay cannot choose a different result because its wall clock is faster. An infrastructure failure while shrinking retains the established pair alongside the engine failure.

## Files & key types

- `runner.rs` — `TestRunner` holds the `Config`, the `successes` / `local_rejects` / `global_rejects` counters, a `TestRng`, a shared `flat_map_regens` atomic, and per-`Reason` rejection tallies. Constructors: `new` (random seed, default algorithm), `deterministic` (fixed seed), `new_with_rng`, `Default`; `partial_clone` (pub(crate)) keeps the config and the shared atomic but resets local state with an independent deterministic child RNG. Public surface used by strategies/combinators: `rng` / `new_rng`, `reject_local` (errors past `max_local_rejects`), `flat_map_regen` (atomically bumps the shared counter, returns whether still under `max_flat_map_regens`), and `run_one` (run a pre-built `ValueTree`; ignores fork). Verbosity constants live here — `ALWAYS = 0`, `pub INFO_LOG = 1` (failures, and state-machine transitions), `TRACE = 2` — emitted via the `verbose_message!` macro, which routes through the `diagnostics` seam under `std` and is a no-op without it.
- `config.rs` (the `Config` type) — aliased as `ProptestConfig` in the prelude; companion `RngSeed` enum is `Random | Fixed(u64)`. The `std` `Default` clones a `LazyLock` `DEFAULT_CONFIG` that defaults `failure_persistence` to `FileFailurePersistence` and runs the env overlay once; off-`std` it falls back to `default_default_config()` (persistence `None`). `PartialEq` is hand-written and compares the `result_cache` function pointer by address (`core::ptr::fn_addr_eq`). Field semantics worth knowing: `cases` defaults to 256; `max_shrink_iters` defaults to `u32::MAX` meaning auto (`cases * 4`) and `0` disables shrinking; `timeout > 0` implies forking; `verbose`, `max_shrink_time`, `fork`, and `timeout` are themselves `#[cfg]`-gated fields.
- `config.rs` (the env overlay) — `contextualize_config` overlays the `PROPTEST_*` vars onto the config; without `std` (or on `wasm32`) it is a different `#[cfg]` body that returns the config unchanged, so **env vars are a no-op off-`std`**. Vars read (all require `std`; the last two additionally require their feature): `PROPTEST_CASES`, `PROPTEST_MAX_LOCAL_REJECTS`, `PROPTEST_MAX_GLOBAL_REJECTS`, `PROPTEST_MAX_FLAT_MAP_REGENS`, `PROPTEST_MAX_SHRINK_TIME`, `PROPTEST_MAX_SHRINK_ITERS`, `PROPTEST_MAX_DEFAULT_SIZE_RANGE`, `PROPTEST_VERBOSE`, `PROPTEST_RNG_ALGORITHM`, `PROPTEST_RNG_SEED`, `PROPTEST_DISABLE_FAILURE_PERSISTENCE`, `PROPTEST_FORK`, `PROPTEST_TIMEOUT`. A parse failure warns and keeps the default; any other `PROPTEST_*` name warns as unknown.
- `errors.rs` — `TestCaseError` is what one case returns: `Reject(Reason)` (regenerate and try again, counts as neither pass nor fail) or `Fail(Reason)`. It is deliberately *not* an `Error` impl so the blanket `From<E: Error>` can route any error into `Fail`. `TestError<T>` is the whole-test outcome: `Abort(Reason)` or `Fail(Reason, T)` carrying the minimized input `T`. `TestCaseResult = Result<(), TestCaseError>` is the public alias; the crate-internal `TestCaseOk` / `TestCaseResultV2` carry the success *kind* that decides whether a pass counts toward `cases`. `ProptestResultExt::prop_assume_ok` (sealed, `#[track_caller]`) turns an `Err` into a `Reject` tagged with the caller location.
- `reason.rs` — `Reason(Cow<'static, str>)`, the human-readable message wrapper for rejects and failures; `From<&'static str | String | Box<str>>`, and it derives `Ord` / `Hash` so it can key the rejection-tally `BTreeMap`.
- `rng.rs` — `TestRng` (public, seedable, reproducible across systems and proptest versions) over the private `TestRngImpl`, plus `RngAlgorithm` (`#[non_exhaustive]`, default `ChaCha`): `XorShift` (16-byte seed, the pre-0.9.1 default), `ChaCha` (32-byte, current default), `PassThrough` (replays raw bytes as "randomness" for fuzzing — splits its buffer evenly across derived RNGs, yields zeros once depleted), and `Recorder` (a ChaCha that also captures the bytes it emits, retrievable via `bytes_used()`). The crate-internal `Seed` enum is the persisted form: `try_from_bytes` validates the per-algorithm length with a typed `SeedLengthError` (`from_bytes` delegates, preserving `TestRng::from_seed`'s documented panic contract and its exact legacy message), and `from_persistence` / `to_persistence` are the wire codec (index-free: `split_first`, slice patterns, `as_chunks`). Seed derivation: `new_rng` → `gen_rng` produces an independent deterministic child (XorShift perturbs with a `deadbeef` mask so a child never equals its parent; `PassThrough` halves the remaining range). `default_rng` seeds from the OS (`SysRng`) under `std`, from safe `getrandom::fill` under `no_std` + x86/x86_64 + `hardware-rng` (OS-less RDRAND consumers select `getrandom_backend="rdrand"` at build time), otherwise from the hard-coded `deterministic_rng`.
- `result_cache.rs` — `ResultCache::put` / `get` store `EvaluationId`; payloads remain in the execution adapter. `ResultCacheKey` exposes the candidate's `Debug` representation to the selected policy. `noop_result_cache` is the default; `basic_result_cache` (`std`) hashes that representation. Choose a factory via `Config::result_cache`.
- `execution.rs` / `typed.rs` — the shared algorithm's adapter contract and typed payload owner. `PropertyRun` preserves evaluations, cache/backtrack events, and counters; the final cause owns the selected assertion failure exactly once.
- `outcome.rs` / `transport.rs` — public native evidence, distinct assertion and engine failure causes, and the caller-selected `PropertyTransport<V, A, E>`. In-process execution imposes no codec bounds. A codec's `restore` and `restore_interrupted` reconcile shared case state before the next shrink step.
- `typed_fork.rs` / `typed_replay.rs` — typed process supervision and versioned framed replay. A complete record carries identity, origin, and payload; incomplete records cannot become evaluations. The parent reconstructs the decoded prefix without invoking the property, preserving protocol, codec, I/O, timeout, child-exit, and cleanup failures separately. The runner owns temporary-file finalization and retains finalization errors alongside any primary failure.
- `replay.rs` (`#[cfg(feature = "fork")]`, crate-internal) — `Replay { seed, steps }` and `ReplayFileStatus` (`InProgress` / `Terminated` / `Corrupt`). The fork file is a sentinel line, then the persisted seed, then an unterminated run of `+` / `-` / `!` / `.` / ` ` chars (pass / fail / reject / terminate / ping), shaped so a child can blindly *append* atomically; `parse_from` requires the sentinel first as a symlink-attack guard. This file legitimately names `std::` directly (fork implies `std`).
- `scoped_panic_hook.rs` (`#[cfg(feature = "std")]`, crate-internal) — exposes `suppress_panic_hook(body)`, implemented without `unsafe`. With the `handle-panics` feature it installs a process-global dispatching panic hook once (saving the hook it replaced in a `OnceLock`) and holds a thread-local suppression flag for the duration of `body` (the prior flag value is restored by a drop guard, so nesting and unwinding are safe): the dispatcher drops panic reports raised on a suppressing thread and forwards every other panic to the saved previous hook, letting the runner silence intermediate panic backtraces during shrinking without interrupting the unwind; without `handle-panics`, `suppress_panic_hook` simply runs `body` and the default hook still prints.
- `diagnostics.rs` (`#[cfg(feature = "std")]`, crate-internal) — the typed `RunnerDiagnostic` catalog behind every runtime warning/hint the runner prints: env-var overlay warnings, failure-persistence hints and resolve warnings, `verbose_message!` output, and the closure-mode fork warning. Each variant renders its legacy text via `Display`, and one best-effort stderr seam writes it with a trailing newline, deliberately dropping write errors so a closed stderr never aborts a run.
- `failure_persistence/` — pluggable storage for minimized failing seeds, selected via `Config::failure_persistence` and driven by the loop above. See its own `AGENTS.md` for the trait, backends, and on-disk format.

## Fork & timeout (`#[cfg(feature = "fork")]`; `timeout` builds on it)

`run_in_fork` re-runs the test in a subprocess via `rusty_fork`, coordinating through a `tempfile` "forkfile" that holds the `Replay`. It loops spawning children (each child runs `run_in_process` and appends its step log), reads the log back to reconstruct progress, synthesizes failures for crashes / nonzero or spurious-success exits / timeouts, and bails if the child dies before the first case or after 10000 child processes. `await_child` / `await_child_without_timeout` wait on the child; the timeout variant kills it once the forkfile stops growing for a full timeout window. `init_replay` detects the child role via the `_PROPTEST_FORKFILE` env var. After the run terminates, the parent replays the recorded steps in-process — without re-running the real test — to recover the shrunken value and update persistence. `ForkOutput` is the no-op shim used when not in a fork (and when the `fork` feature is off).

## Gotchas

- Respect the feature gates when editing across files: `replay` is `fork`-only, `scoped_panic_hook` is `std`-only, its panic-suppression behaviour is further `handle-panics`-only, and the `fork` / `timeout` / `max_shrink_time` / `verbose` `Config` fields are `#[cfg]`-gated. `Config::PartialEq`, `Default`, and `contextualize_config` all mirror that gating and must stay in lockstep with the field set.
- Counting is subtle: only genuinely new cases advance `successes` toward `cases`; persisted-failure replays, cache hits, and rejects do not. If you touch this, keep `TestCaseOk` and the `successes` bump in `gen_and_run_case` consistent.
- The seed is generated *before* the case runs (`gen_get_seed`) precisely so a failing case can be persisted and replayed deterministically — don't reorder that, and keep the RNG save/restore around the persisted-replay phase intact.
