# AGENTS.md

This file provides guidance to coding agents when working with code in this repository.

Scope: `proptest-state-machine/examples/` — the canonical worked examples for this crate; the Proptest Book's "State Machine testing" chapter (`book/src/proptest/state-machine.md`) walks through both. Each file is self-contained, keeping its real implementation in an inlined `system_under_test` module. For the trait surface (`ReferenceStateMachine`, `StateMachineTest`) see the crate's `../src/AGENTS.md`; for shared conventions see the workspace-root `AGENTS.md`.

## Shared shape

Both examples follow the same skeleton, and both are written to **fail on purpose** so they double as a shrinking demo:

- A `prop_state_machine!` block sets `failure_persistence: None` (no `proptest-regressions/` file is written) and `verbose: 1` (each applied transition prints to stdout, so you don't need `PROPTEST_VERBOSE`). The leading keyword is `sequential` (the only mode supported), and `1..20` is the per-case transition-count range.
- The `#[test]` attribute inside the macro is **commented out** and a `fn main() -> StateMachinePropertyResult<ConcreteTest>` returns the generated function's verdict instead, so each file is an *example binary*, not a test, and a falsified property reports through the exit status rather than a panic: `cargo run --example` runs the demonstrations. Adjacent unit tests run under `cargo test -p proptest-state-machine --all-targets`.
- The real code lives in an inlined `mod system_under_test`, and the planted bug stays on the default path: `state_machine_heap.rs` calls `pop_wrong`, while `state_machine_echo_server.rs` selects `SendImplementation::Immediate` for `msg_server`. Correct behavior remains present as exercised code (`pop` has its own focused test; `SendImplementation::WaitUntilConnected` is the alternate branch) instead of dead-code fixtures.

```sh
cargo run -p proptest-state-machine --example state_machine_heap
cargo run -p proptest-state-machine --example state_machine_echo_server
```

## `state_machine_heap.rs`

Models a hand-rolled max-heap (`MyHeap<i32>`). The simplest case: the basic two-trait split and clean shrinking, no preconditions, no I/O.

- Reference model: `HeapStateMachine` (a unit struct) with `State = Vec<i32>` and `Transition = Pop | Push(i32)`. `init_state` is the empty vec; `transitions` is a weighted `prop_oneof![1 => Pop, 2 => Push(any::<i32>())]` (pushes twice as likely as pops); `apply` mirrors each transition onto the `Vec`. There is no `preconditions` override, so `Pop` is generated even against an empty heap — the SUT copes via its `None`/`was_empty` branch.
- System under test: `MyHeap<i32>` implements `StateMachineTest` (`Reference = HeapStateMachine`). Its `apply` retains the heap, popped value, and prior emptiness in native checks; `HeapFailure` preserves a failed post-condition. Successful application evidence retains the heap values and pop observation; invariant evidence retains `(len, is_empty)`.
- The bug: `pop_wrong` does `swap_remove(0)` without sifting the moved element back down, returning the true max once but corrupting the heap. The run fails and shrinks to a minimal failing sequence — it needs **two** `Pop`s (the first always returns the genuine maximum; only a later pop sees the order `pop_wrong` broke) plus enough `Push`es to leave a value behind for the assertion to catch. Pass `--correct` to select `pop`; adjacent tests cover both corrected ordering and the planted failure with prior transition evidence.

## `state_machine_echo_server.rs`

Models an echo server with multiple concurrent clients over real sockets, using the `message-io` dev-dependency (workspace `0.19.0`, features `tcp`/`udp`/`websocket`). The advanced case: real threads, real I/O, and `preconditions`.

- Reference model: `RefState` is its own `State` and tracks `is_server_up`, a `HashSet<ClientId>` (`ClientId = usize`), and a `Transport` chosen at random in `init_state` (`Tcp` / `FramedTcp` / `Udp` / `Ws`). `Transition` is `StartServer | StopServer | StartClient(id) | StopClient(id) | ClientMsg(id, Msg)` (`Msg = String`, generated by the `"[a-z0-9]{1,8}"` regex strategy in `arb_msg_from_client`); `transitions` only offers client-targeting transitions once a client exists, choosing an existing id with `proptest::sample::select`.
- `preconditions` is the key addition over the heap example: it gates every transition on the model state (no starting an already-running server, no messaging a stopped client, etc.). This matters because shrinking deletes and reorders transitions, so each one's validity is re-checked against the (possibly changed) state before it is applied — see `../src/AGENTS.md`.
- System under test: `EchoServerTest` holds an `Option<TestServer>` and a `HashMap<ClientId, TestClient>`. `StartServer`/`StartClient` each spawn a `message-io` listener thread; the server binds `127.0.0.1:0` (OS-assigned port) and clients connect to the resolved address. A client listener forwards received echoes over an `mpsc` channel; the trait impl returns native `EchoObservation` or `EchoFailure` values preserving resource owners, messages, send statuses, receive results, and joined shutdown results. The one-second `recv_timeout()` bounds the echo wait.
- The bug, and the gotcha: `ClientMsg` calls `msg_server` with `SendImplementation::Immediate`, which writes to the socket *without* waiting for the connection to be established, so an early message can be dropped. Lost messages now surface as a concrete `EchoFailure` through either a non-`Sent` `SendStatus` or a one-second receive timeout instead of hanging the example. Pass `--correct` to select `WaitUntilConnected`, which waits on the shared connection flag before sending. The macro's `cases` field is an inner-driver value; use `PROPTEST_CASES=10` to cap outer property cases and limit thread/socket churn. The real-socket lifecycle test checks messages and server-before-client shutdown joins; failure tests retain absent-resource state and unsent messages.
