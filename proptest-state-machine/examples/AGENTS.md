# AGENTS.md

This file provides guidance to coding agents when working with code in this repository.

Scope: `proptest-state-machine/examples/` — the canonical worked examples for this crate; the Proptest Book's "State Machine testing" chapter (`book/src/proptest/state-machine.md`) walks through both. Each file is self-contained, keeping its real implementation in an inlined `system_under_test` module. For the trait surface (`ReferenceStateMachine`, `StateMachineTest`) see the crate's `../src/AGENTS.md`; for shared conventions see the workspace-root `AGENTS.md`.

## Shared shape

Both examples follow the same skeleton, and both are written to **fail on purpose** so they double as a shrinking demo:

- A `prop_state_machine!` block sets `failure_persistence: None` (no `proptest-regressions/` file is written) and `verbose: 1` (each applied transition prints to stdout, so you don't need `PROPTEST_VERBOSE`). The leading keyword is `sequential` (the only mode supported), and `1..20` is the per-case transition-count range.
- The `#[test]` attribute inside the macro is **commented out** and a `fn main() -> proptest::strict::TestResult` returns the generated function's verdict instead, so each file is an *example binary*, not a test, and a falsified property reports through the exit status rather than a panic: `cargo test -p proptest-state-machine` does **not** run these — use `cargo run --example`.
- The real code lives in an inlined `mod system_under_test`, and the planted bug is an intentionally-wrong function (`pop_wrong` / `msg_server_wrong`). Each has a correct sibling (`pop` / `msg_server`, marked `#[allow(dead_code)]`) and an inline comment naming the two lines to swap to watch the test pass.

```sh
cargo run -p proptest-state-machine --example state_machine_heap
cargo run -p proptest-state-machine --example state_machine_echo_server
```

## `state_machine_heap.rs`

Models a hand-rolled max-heap (`MyHeap<i32>`). The simplest case: the basic two-trait split and clean shrinking, no preconditions, no I/O.

- Reference model: `HeapStateMachine` (a unit struct) with `State = Vec<i32>` and `Transition = Pop | Push(i32)`. `init_state` is the empty vec; `transitions` is a weighted `prop_oneof![1 => Pop, 2 => Push(any::<i32>())]` (pushes twice as likely as pops); `apply` mirrors each transition onto the `Vec`. There is no `preconditions` override, so `Pop` is generated even against an empty heap — the SUT copes via its `None`/`was_empty` branch.
- System under test: `MyHeap<i32>` implements `StateMachineTest` (`Reference = HeapStateMachine`). Its `apply` runs the buggy `pop_wrong` and `ensure`s the max-heap post-condition — the popped value must be `>=` every value still in the heap — plus emptiness consistency, returning `Err(TestFailure)` on violation; `check_invariants` returns the `ensure` result that `len()` and `is_empty()` agree.
- The bug: `pop_wrong` does `swap_remove(0)` without sifting the moved element back down, returning the true max once but corrupting the heap. The run fails and shrinks to a minimal failing sequence — it needs **two** `Pop`s (the first always returns the genuine maximum; only a later pop sees the order `pop_wrong` broke) plus enough `Push`es to leave a value behind for the assertion to catch. Swap `pop_wrong` → `pop` to make it pass.

## `state_machine_echo_server.rs`

Models an echo server with multiple concurrent clients over real sockets, using the `message-io` dev-dependency (workspace `0.19.0`, features `tcp`/`udp`/`websocket`). The advanced case: real threads, real I/O, and `preconditions`.

- Reference model: `RefState` is its own `State` and tracks `is_server_up`, a `HashSet<ClientId>` (`ClientId = usize`), and a `Transport` chosen at random in `init_state` (`Tcp` / `FramedTcp` / `Udp` / `Ws`). `Transition` is `StartServer | StopServer | StartClient(id) | StopClient(id) | ClientMsg(id, Msg)` (`Msg = String`, generated by the `"[a-z0-9]{1,8}"` regex strategy in `arb_msg_from_client`); `transitions` only offers client-targeting transitions once a client exists, choosing an existing id with `proptest::sample::select`.
- `preconditions` is the key addition over the heap example: it gates every transition on the model state (no starting an already-running server, no messaging a stopped client, etc.). This matters because shrinking deletes and reorders transitions, so each one's validity is re-checked against the (possibly changed) state before it is applied — see `../src/AGENTS.md`.
- System under test: `EchoServerTest` holds an `Option<TestServer>` and a `HashMap<ClientId, TestClient>`. `StartServer`/`StartClient` each spawn a `message-io` listener thread; the server binds `127.0.0.1:0` (OS-assigned port) and clients connect to the resolved address. A client listener forwards received echoes over an `mpsc` channel; the trait impl verifies them through `ensure_some`/`ensure_ok`/`ensure_eq` (presence lookups, the one-second echo `recv_timeout()`, and the echo post-condition all return `TestFailure` instead of unwrapping).
- The bug, and the gotcha: `ClientMsg` sends via `msg_server_wrong`, which writes to the socket *without* waiting for the connection to be established, so an early message can be dropped. Lost messages now surface as a returned `TestFailure` through either a non-`Sent` `SendStatus` or a one-second receive timeout instead of hanging the example. Swap `msg_server_wrong` → `msg_server` (which busy-waits on the shared `is_connected` flag before sending) to make it pass. `cases` is capped at `10` here to limit thread/socket churn.
